# مراجعة أكاديمية للتصميم الحالي

التاريخ: 1 نوفمبر 2026. النطاق: 13 مصدر PlantUML و16 معاينة، وأوصاف حالات الاستخدام العشر وحصر المتطلبات وقالب التقرير المرفق. تفاصيل التصحيحات وتتبّع المتطلبات في [مراجعة المحتوى](DESIGN_CONTENT_REVIEW_2026-11-01.md).

## الحكم الحالي

الحزمة مسودة تصميم موثقة يمكن استكمالها والبناء عليها. لا تعني كثرة الرسوم أو نجاح تصديرها اكتمال SRS أو قبول المشرف أو تنفيذ المنصة. مرجع التسليم هو قالب الجامعة وتعليمات المشرف؛ المعايير التالية مراجع فنية مساندة.

الحصر الحالي: **28 متطلبًا وظيفيًا رئيسيًا، و10 حالات استخدام موصوفة، و24 فحصًا ضمن FR-11**. لا تضاف هذه الأعداد إلى بعضها. يوضح [فهرس المخططات](diagrams/README.md) الملفات الحالية فقط.

## ما تحقق في التوثيق

| الجانب | الحالة الحالية وحدودها |
|---|---|
| Use Case | أدوار وحالات داخل حدود النظام، مع معرفات UC وخطوط مشاركة عادية. المناظر الثلاثة للنظام نفسه، وليست ثلاثة أنظمة أو مصفوفة صلاحيات كاملة |
| Include وExtend | لا توجد حاجة مثبتة لإضافتهما حاليًا؛ تستخدمان لمعنى سلوكي محدد، ولا تمثلان كل استدعاء داخلي |
| Activity | بداية ونهاية وأعمال وقرارات ودمج وحراسات بين أقواس مربعة. صححت فروع الحفظ والإلغاء والتحقق؛ الحالات البديلة المفصلة موثقة في أوصاف الاستخدام |
| Context وContainer | منظوران من C4 يوضحان حدود النظام والتطبيقات ومخزن البيانات وعلاقاتها. استخدام PlantUML لا يحولهما إلى مخططات UML |
| التتبع | ربط تصميمي للمتطلبات الرئيسية بالحالات؛ لا يمثل نتائج اختبار قبول أو اكتمال المتطلبات غير الوظيفية |
| حالة الإنجاز | الوثائق موسومة تصميمًا مستهدفًا؛ المنصة وتكامل GitHub الحي لم يُنفذا ضمن هذا العمل |

## ما يجب استكماله

1. تفصيل المصادقة وتهيئة المؤسسة والمسؤول الأول واسترداد الوصول؛ اعتُمدت [مصفوفة الصلاحيات](ACCESS_CONTROL_MATRIX.md) في AC-01 بتاريخ 1 نوفمبر 2026.
2. عقود تكامل GitHub والصلاحيات والمهام، ثم Component وDomain/ERD وSequence وState وتدفق البيانات والنشر حيث تحتاجها متطلباتنا.
3. معايير قبول قابلة للاختبار لمتطلبات الوظائف والأمن والجودة. الحصر الحالي ليس SRS نهائية.
4. إخراج التقرير الجامعي باللغة والتنسيق المطلوبين، مع عنوان وترقيم وشرح وإحالة لكل شكل. تراجع الرسوم الطويلة عند إدراجها بحجم الشريحة أو الصفحة الفعلي.

## الخط واللغة

Dubai هو خط نسخة العمل العربية الحالية. القالب المرفق يطلب الإنجليزية والخط الرئيسي Times New Roman؛ لا توجد لدينا موافقة خاصة على Dubai داخل الأشكال النهائية. راجعت سابقًا نص الصفحة 25 وصورتها، وسجلت التفاصيل في [حصر القالب](REPORT_TEMPLATE_REQUIREMENTS.md). الأصل محفوظ محليًا وليس ضمن حزمة النشر.

## المراجع وحدود استخدامها

| المرجع | ما استخدم في المراجعة |
|---|---|
| [UML 2.5.1 — المواصفة الرسمية](https://www.omg.org/spec/UML/2.5.1/PDF) | الأقسام 18.1.3–18.1.4 لحالات الاستخدام، و11.5.4 للارتباط، و15.2.4 و15.3.4.3 لتدفق النشاط والقرار والدمج؛ قرئت الأجزاء ذات الصلة من النسخة الرسمية المحفوظة محليًا |
| [ISO/IEC/IEEE 29148:2018](https://www.iso.org/standard/72089.html) | الصفحة الرسمية العامة ونطاق هندسة المتطلبات؛ لم يراجع النص المدفوع كاملًا |
| [ISO/IEC/IEEE 42010:2022](https://www.iso.org/standard/74393.html) | الصفحة الرسمية العامة ونطاق وصف المعمارية؛ لا ندعي تدقيق مطابقة بندًا بندًا |
| [C4 model](https://c4model.com/diagrams) | معاني السياق وContainers وComponents واختيار المناظير التي تضيف قيمة |

هذه مراجعة فنية للتوثيق، وليست شهادة مطابقة ISO أو إقرار قبول أكاديمي. يحتفظ Git بتاريخ التعديلات؛ تعرض هذه الصفحة الحالة الحالية بدل أعداد المراحل السابقة.
