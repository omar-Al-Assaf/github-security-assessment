# UC01 — إدارة العضويات والأدوار

الحالة: تصميم مستهدف. التاريخ: 1 نوفمبر 2026.

| العنصر | الوصف |
|---|---|
| الهدف | إدارة عضويات مؤسسة المنصة وإسناد دور محدد لكل عضوية، مع حماية حدود المؤسسة واستمرار وجود مسؤول فعال |
| الطرف الرئيسي | مسؤول المؤسسة المخول بإدارة العضويات |
| المحفز | اختيار إضافة عضوية أو تغيير دور عضو أو تعطيل عضويته أو إعادة تفعيلها |
| المدخلات | المؤسسة، وهوية المستخدم أو مرجع العضوية المستهدفة، والإجراء المطلوب، والدور عند الإضافة أو تغييره، ومرجع النسخة الحالية عند التعديل |
| الشروط السابقة | مؤسسة مسجلة لها مسؤول فعال؛ جلسة وعضوية وصلاحية إدارة صالحة للفاعل. إضافة عضوية تربط بهوية مستخدم موجودة ومتحقق منها وفق آلية مصادقة المنصة |
| النتيجة الناجحة | عضوية محدثة ودور وحالة محفوظان، مع تسجيل الفاعل والتغيير والوقت |
| ضمان الفشل | لا يمنح صلاحيات في مؤسسة أخرى، ولا يعطل آخر مسؤول فعال، ولا يعلن نجاح تغيير لم يُحفظ |

## معنى العضوية والدور

- العضوية تربط مستخدمًا بمؤسسة محددة. يحمل كل ارتباط دورًا واحدًا من الأدوار الثلاثة المعتمدة: مسؤول أو مقيّم أو مراجع؛ يمكن للمسؤول المخول تغيير هذا الإسناد.
- المستخدم نفسه قد تكون له عضويات في مؤسسات مختلفة بأدوار مختلفة. لا يصبح مسؤولًا في مؤسسة ثانية بسبب دوره في الأولى.
- المسؤول يدير العضويات والاتصال والسياسة ويستطيع التشغيل والاطلاع، والمقيّم يدير دورة التقييم والمعالجة والتخطيط، والمراجع يراجع النتائج والأدلة والتقارير. تفصل [مسودة مصفوفة الصلاحيات](../ACCESS_CONTROL_MATRIX.md) الإجراءات والقيود؛ الدور واحد لكل عضوية، والقائمة المسموحة لكل إجراء صريحة.
- عضوية المنصة مستقلة عن عضوية GitHub وعن البوتات والأطراف التي يحلل المحرك صلاحياتها. إسناد دور في المنصة لا يمنح بذاته صلاحية على GitHub.

## المسار الأساسي

1. يختار المسؤول مؤسسته ويفتح إدارة العضويات. تتحقق المنصة من جلسة الفاعل وعضويته الفعالة وصلاحيته داخل هذه المؤسسة قبل عرض بيانات الأعضاء.
2. تعرض عضويات المؤسسة وأدوارها وحالاتها. يختار المسؤول إضافة عضوية أو تعديل عضوية قائمة أو تعطيلها أو إعادة تفعيلها.
3. عند الإضافة، يحدد هوية مستخدم متحقق منها والدور المطلوب. تتحقق المنصة من المرجع دون إتاحة استعراض بيانات مستخدمين غير مخولة، ومن عدم وجود عضوية مكررة للمستخدم والمؤسسة نفسيهما. عند التعديل، تختار العضوية من المؤسسة الحالية وتبقى هويتها وتاريخها محفوظين.
4. يحدد المسؤول القيم الجديدة ويراجع ملخص التغيير، بما فيه الصلاحيات التي ستتغير، ثم يؤكد الطلب. لا يعدل هذا الإجراء هوية المستخدم أو بيانات دخوله أو عضوياته في مؤسسات أخرى.
5. تتحقق المنصة من الإجراء والدور ومرجع العضوية، ومن بقاء مسؤول فعال واحد على الأقل بعد التغيير. ينطبق ذلك على تعطيل آخر مسؤول أو خفض دوره، بما فيه تعديل الفاعل لعضويته هو.
6. تعيد التحقق من تفويض الفاعل والنسخة الحالية وقت الحفظ، وتحفظ التغيير وسجل التدقيق بصورة متسقة. يحمي التنفيذ شرط آخر مسؤول عند الطلبات المتزامنة؛ لا يكفي عد الأعضاء في صفحة سبق فتحها.
7. تعرض النتيجة المحفوظة. يسري الدور أو التعطيل على طلبات الوصول اللاحقة؛ لا يبقى الوصول مباحًا لمجرد أن المستخدم فتح صفحة قبل سحب صلاحيته. تراجع المهام غير النهائية استمرار صلاحية طالبها وفق المصفوفة، دون فصل اتصال المؤسسة أو إلغاء مهام الآخرين تلقائيًا.
8. تبقى التقييمات والأدلة والتعليقات وسجلات التدقيق السابقة مرتبطة بفاعلها وتاريخها. تعطيل العضوية أو إعادة تفعيلها لا يمحو التاريخ أو ينشئ عضوية مكررة.

## البدائل والاستثناءات

| الرمز | الحالة | السلوك المطلوب |
|---|---|---|
| A1 | جلسة غير صالحة أو فاعل غير مخول أو عضوية تخص مؤسسة أخرى | رفض الإجراء دون كشف بيانات الأعضاء أو تعديلها |
| A2 | هوية مستخدم غير صالحة أو غير متحقق منها أو دور خارج القائمة المعتمدة | توضيح تعذر قبول الطلب دون إنشاء حساب أو صلاحية مفترضة |
| A3 | إضافة عضوية موجودة أصلًا | عدم تكرارها؛ تعديل العضوية القائمة أو إعادة تفعيلها يحتاج الإجراء المخول المناسب |
| A4 | تعطيل آخر مسؤول فعال أو خفض دوره | رفض التغيير؛ يمكن أولًا إسناد دور المسؤول إلى عضو آخر مخول ثم إعادة الطلب |
| A5 | تغيرت عضوية الفاعل أو العضوية المستهدفة أثناء المراجعة | إعادة فحص التفويض والقيم الحالية، وطلب مراجعة التغيير عند التعارض؛ لا يكتب فوق تحديث أحدث بصمت |
| A6 | فشل الحفظ أو سجل التدقيق | عدم تأكيد نجاح التغيير؛ تبقى الحالة السابقة المعتمدة مرجعًا |
| A7 | إلغاء المسؤول قبل الحفظ | تبقى العضوية والدور والحالة دون تعديل |

## ضوابط وحدود الحالة

- تفحص الصلاحيات في الخادم لكل إجراء؛ إخفاء أزرار الإدارة وحده لا يمنع طلبًا غير مخول.
- لا يعدل المستخدم دوره بنفسه دون امتلاك صلاحية الإدارة أصلًا، ولا يتجاوز شرط آخر مسؤول إذا كان هو العضو المستهدف.
- تعطيل عضوية المنصة لا يلغي تثبيت GitHub App ولا يغير عضويات GitHub أو بيانات المؤسسة المحفوظة. إدارة الاتصال وظيفة UC02.
- هذا السيناريو يبدأ من مؤسسة لها مسؤول فعال. يجب توثيق تهيئة المؤسسة والمسؤول الأول واسترداد الوصول ضمن تصميم المصادقة قبل التنفيذ؛ لا يستنتج من هذه الحالة وجود مسار تسجيل عام أو دعوات بريدية منفذة.
- هذه تفاصيل ضبط للمتطلبات القائمة FR-02 وFR-03 وFR-26؛ ليست أدوارًا جديدة أو متطلبات رئيسية إضافية لمجرد تفصيل خطوات الحالة.
