# UC02 — إدارة اتصال GitHub

الحالة: تصميم مستهدف. التاريخ: 1 نوفمبر 2026.

| العنصر | الوصف |
|---|---|
| الهدف | ربط المؤسسة بتثبيت GitHub App مصرح به، وتحديد نطاق القراءة وإظهار جاهزيته، مع إمكان تحديث الاتصال أو فصله محليًا |
| الطرف الرئيسي | مسؤول المؤسسة المخول داخل المنصة |
| الطرف الخارجي | GitHub، للتحقق من الهوية والتفويض والتثبيت والوصول الفعلي |
| المحفز | اختيار «ربط GitHub»، أو «تحديث حالة الاتصال»، أو «فصل الاتصال» |
| المدخلات | المؤسسة، والتثبيت المتحقق منه، والمستودعات المختارة من النطاق المصرح به |
| الشروط السابقة | جلسة صالحة وصلاحية إدارة الاتصال داخل المؤسسة؛ GitHub App مسجلة ومهيأة لاستقبال مسار الربط، ويمكن تثبيتها في الحساب المستهدف |
| النتيجة الناجحة | اتصال محفوظ تابع للمؤسسة، مع معرفات التثبيت والحساب والمستودعات وحدود الوصول ووقت آخر تحقق |
| ضمان الفشل | لا يربط تثبيتًا اعتمادًا على معرف وارد من المتصفح وحده، ولا يكشف بيانات مؤسسة أخرى، ولا يحول غياب البيانات إلى نجاح فحص |

## المسار الأساسي — إنشاء الاتصال

1. يختار المسؤول مؤسسته ويطلب ربط GitHub. تتحقق المنصة من الجلسة وصلاحية إدارة الاتصال داخل هذه المؤسسة.
2. تنشئ المنصة محاولة ربط مرتبطة بالمستخدم والمؤسسة، مع قيمة `state` مؤقتة للاستخدام مرة واحدة لمنع خلط الطلبات وCSRF.
3. ينتقل المسؤول إلى GitHub لتفويض GitHub App وتثبيتها أو إعداد تثبيت قائم. قد تحتاج العملية موافقة مالك المؤسسة على GitHub؛ صلاحية المسؤول داخل منصتنا وحدها لا تمنح هذه الموافقة.
4. عند العودة، تتحقق المنصة من محاولة الربط، ومن هوية GitHub عبر تفويض المستخدم، ومن ارتباط التثبيت بهذه الهوية وبالتطبيق والحساب المقصودين. تتحقق أيضًا من صلاحية إدارة النطاق؛ مجرد إمكانية رؤية التثبيت لا يثبت هذه الصلاحية. لا يكفي `installation_id` أو `state` وحده لإثبات التفويض.
5. تتحقق المنصة من عدم استخدام التثبيت لربط مؤسسة أخرى دون إجراء نقل مخول. ثم تستعلم من الخادم عن المستودعات التي يتيحها التثبيت فعلًا، مع استكمال الصفحات اللازمة.
6. يختار المسؤول المستودعات المطلوبة من القائمة المصرح بها. نطاق المنصة هو تقاطع اختياره مع ما يتيحه التثبيت؛ لا تتوسع المهام إلى مستودعات أخرى لمجرد إمكان قراءتها تقنيًا.
7. تتحقق المنصة من الوصول اللازم للفحوص ضمن النطاق، وتبين ما يمكن قراءته وما تعذر وسبب ذلك إن كان معلومًا. نجاح الربط لا يعني أن كل الفحوص الـ24 متاحة؛ بعض البيانات تتأثر بالصلاحيات والاشتراك وتوافر الخدمة.
8. تحفظ بيانات الاتصال والنطاق ووقت التحقق وحدوده، وتسجل الإجراء في سجل التدقيق، ثم تعرض الحالة للمسؤول. لا تبدأ تقييمًا أو تطبيق إصلاح تلقائيًا.

## تحديث الحالة أو النطاق

يعيد المسؤول المخول طلب التحقق من التثبيت والصلاحيات والمستودعات المتاحة، ثم يحفظ الاختيار المحدث. عند سحب وصول مستودع لا يظل صالحًا للتنفيذ لمجرد وجوده في اختيار قديم. تعاد مراجعة الوصول أثناء تنفيذ UC05 أيضًا؛ حالة الاتصال المعروضة مقيدة بوقت آخر تحقق، وليست ضمانًا دائمًا.

إذا علق التثبيت أو ألغي من GitHub، يظهر ذلك عند التحقق أو محاولة التنفيذ التالية. استقبال Webhooks لإبلاغ المنصة فورًا ليس ضمن النطاق الحالي.

## فصل الاتصال محليًا

1. يختار المسؤول اتصال مؤسسته ويؤكد فصله؛ تعاد مراجعة صلاحية الإجراء وملكية الاتصال.
2. تحفظ المنصة تعطيل الاتصال قبل تأكيد الفصل وتمنع بدء مهام جديدة عليه. تلغى المهام المنتظرة المرتبطة به، ويطلب إلغاء الجاري منها مع منع قراءات GitHub اللاحقة عند نقاط التحقق. يخص الإلغاء المهام غير النهائية لهذا الاتصال، ولا يغير نتيجة مهمة انتهت بالفعل. لا يعني ذلك توقف طلب شبكة قيد التنفيذ فورًا؛ تعرض الحالة الفعلية حتى ينتهي أو يبلغ مهلته.
3. تحفظ النتائج والأدلة والتاريخ وفق سياسة الاحتفاظ، مع تسجيل من فصل الاتصال ووقته. لا تتغير اتصالات المؤسسات الأخرى ولا يحذف مفتاح التطبيق المشترك.
4. تعرض المنصة أن الفصل محلي. إزالة تثبيت التطبيق من GitHub إجراء منفصل يجريه المخول هناك؛ لا تدعي المنصة حدوثه لمجرد تعطيل الربط المحلي.

## المسارات البديلة والاستثنائية

| الرمز | الحالة | السلوك المطلوب |
|---|---|---|
| A1 | جلسة أو صلاحية غير صالحة، أو اتصال تابع لمؤسسة أخرى | رفض الإجراء دون كشف بيانات الاتصال |
| A2 | إلغاء الربط، أو انتهاء المحاولة، أو عودة غير متطابقة | لا ينشأ اتصال صالح؛ تظهر الحاجة لبدء محاولة ربط جديدة |
| A3 | موافقة GitHub معلقة أو تعذر إثبات صلاحية إدارة النطاق | تعرض حالة انتظار أو تعذر واضحة؛ لا يعتمد الاتصال جاهزًا للتنفيذ |
| A4 | وصول جزئي أو خطأ `403` أو `404` أو بيانات ناقصة | توثق حدود الوصول؛ لا يستنتج تعطيل إعداد أمني بمجرد خطأ القراءة |
| A5 | التثبيت مرتبط بمؤسسة أخرى داخل المنصة | يرفض الربط التلقائي؛ لا تنقل البيانات أو الملكية بإدخال معرف التثبيت |
| A6 | عطل GitHub أو حد طلبات أثناء التحقق | تظهر الحالة غير المتحقق منها حديثًا مع آخر وقت معلوم، دون محو التاريخ أو ادعاء استمرار الجاهزية |
| A7 | فشل حفظ الربط أو تعديل نطاقه | لا يؤكد نجاح التغيير؛ يبقى آخر وضع محفوظ هو المرجع |
| A8 | انقضاء رمز تثبيت قابل للتجديد | يجدد من الخادم ضمن التفويض القائم؛ لا يطلب من المستخدم إعادة التثبيت لمجرد انتهاء الرمز |

## ضوابط التصميم

- تستخدم مهام الجمع الخلفية تفويض تثبيت التطبيق، وتظل مصادقة المنصة وصلاحيات المؤسسة مستقلة عن امتلاك رمز GitHub. مسار إثبات ربط التثبيت يستخدم تفويض مستخدم GitHub App؛ ليس إدخال PAT يدويًا.
- تحفظ معرفات GitHub الثابتة لربط السجلات، ولا يعتمد الربط على اسم قابل للتغيير وحده.
- تحفظ المفاتيح والرموز في الخادم بحماية مناسبة؛ لا تظهر في الأدلة أو السجلات أو صفحات النتائج. يحدد أسلوب إدارة الأسرار في تصميم النشر، ولا يفرض هذا الوصف منتجًا إضافيًا.
- تطلب أقل صلاحيات لازمة للبيانات المطلوبة. تفصل مصفوفة الفحوص لاحقًا أي استعلام يحتاج صلاحية أوسع؛ منح صلاحية API لا يغير قرار المشروع بأن تطبيق الإصلاح يدوي.
- إعداد الربط والتحقق منه يستدعيان تكامل GitHub من Web. جمع أدلة التقييم ينفذ في Worker؛ محرك التقييم والتخطيط لا يدير المصادقة أو اتصالات الشبكة.
