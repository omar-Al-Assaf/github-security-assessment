# UC03 — ضبط سياسة الفحص وأهداف الأطراف

الحالة: تصميم مستهدف. التاريخ: 1 نوفمبر 2026.

| العنصر | الوصف |
|---|---|
| الهدف | تحديد المتطلبات التي سيُقيّم النطاق على أساسها، وأهداف السماح والمنع وحدود التعديل اللازمة عند طلب خطة إصلاح |
| الطرف الرئيسي | مسؤول المؤسسة المخول بإدارة السياسة |
| المحفز | اختيار إنشاء سياسة أو تعديل سياسة محفوظة أو أهداف إصلاح محفوظة |
| المدخلات | المؤسسة، ومرجع النسخة الحالية عند تعديلها، والفحوص وقيمها المطلوبة وقوائمها المعتمدة، والأهداف وحدود التعديل عند الحاجة |
| الشروط السابقة | جلسة وعضوية صالحتان وصلاحية إدارة السياسة داخل المؤسسة؛ اختيار المراجع المرتبطة بمستودعات أو فروع أو أطراف من نطاق المؤسسة المصرح به |
| النتيجة الناجحة | نسخة محفوظة من السياسة أو الأهداف المعدلة، مع مرجعها وفاعل الاعتماد ووقته؛ يمكن اختيارها لاحقًا للتقييم أو التخطيط |
| ضمان الفشل | لا تُستبدل نسخة مستخدمة في تقييم سابق، ولا يُعتمد إدخال غير صالح أو متعارض، ولا يغير حفظ السياسة إعدادات GitHub |

## ما الذي يحدده المسؤول؟

| الجزء | محتواه | مثال |
|---|---|---|
| سياسة الفحص | معرفات الفحوص المطلوبة، وقيمها وحدودها وقوائم الاعتماد ضمن الكتالوج | اشتراط موافقتين؛ تحديد الاستثناءات المعتمدة؛ تحديد الحد الأقصى لعمر تحليل أمني |
| أهداف الإصلاح | المستودع والفرع والطرف والعملية والنتيجة المطلوبة لكل حالة | منع الدفع القسري عن بوت الإصدار، والسماح بتحديثه الطبيعي، وإبقاء الدفع القسري مسموحًا لبوت المزامنة |
| حدود التعديل | الطبقات القابلة للتعديل والثابتة، وأنواع التعديلات المسموحة ضمن قدرات المحرك | إبقاء مجموعة قواعد موروثة دون تعديل، مع السماح بإضافة مجموعة على المستودع |

الأهداف ليست قائمة استثناءات GitHub نفسها؛ هي السلوك الذي تريد المؤسسة تحقيقه، وقد يتطلب تحقيقه تغيير ترتيب القواعد والاستثناءات. كما أن اعتماد استثناء في سياسة الفحص لا يثبت وحده أن كل أهداف الحماية مستوفاة.

## المسار الأساسي

1. يختار المسؤول مؤسسته، ثم إنشاء سياسة أو فتح نسخة محفوظة لتعديلها. تتحقق المنصة من صلاحياته ومن انتماء المراجع إلى المؤسسة.
2. تعرض المنصة كتالوج الفحوص وحقول إعدادها، والقيم المحفوظة إن وجدت. تحدد السياسة الفحوص المطلوبة وقيمها؛ أما اختيار نطاق تشغيل محدد فيكون في UC04.
3. يضبط المسؤول القيم والحدود والقوائم المعتمدة للفحوص المطلوبة. تتبع أنواع الحقول ومعانيها تعريف كل فحص؛ لا تنشئ المنصة حكمًا أمنيًا من حقل غير محدد المعنى.
4. عند إعداد الإصلاح، يحدد المسؤول أهدافًا صريحة: النطاق، والطرف بمعرفه ونوعه، والعملية، والسماح أو المنع المطلوب. ويحدد الطبقات القابلة للتعديل والثابتة والتعديلات المسموحة. لا يشترط تعريف أهداف إصلاح لتشغيل تقييم عادي، ويمكن تعديل الأهداف دون تغيير سياسة الفحص غير المعنية.
5. تتحقق المنصة من الحقول المطلوبة وأنواع القيم وحدودها وصحة المراجع، ومن التعارضات القابلة للإثبات. مثال التعارض: طلب السماح والمنع للطرف والعملية نفسيهما في النطاق نفسه والظروف نفسها. لا تُحل هذه الحالة باختيار أحد الهدفين تلقائيًا.
6. تعرض المنصة ملخص التغييرات والقيم المطلوبة والأهداف وحدود التعديل. يراجع المسؤول الملخص ويؤكد الحفظ؛ يستطيع إلغاء التعديل مع إبقاء آخر نسخة محفوظة.
7. تعيد المنصة التحقق من التفويض ومن مرجع النسخة التي بدأ منها التعديل. إذا اعتمد مسؤول آخر نسخة أحدث، تطلب مراجعتها قبل الحفظ، ولا تستبدلها بصمت.
8. تحفظ نسخة جديدة من المحتوى المعدل ومرجعها وسجل الإجراء بصورة متسقة، ثم تعرض تأكيدًا ومعرف النسخة. تبقى مراجع سياسة الفحص وأهداف الإصلاح مميزة، ويثبت كل تقييم أو تخطيط المراجع التي استُخدمت فيه.

## البدائل والاستثناءات

| الرمز | الحالة | السلوك المطلوب |
|---|---|---|
| A1 | مستخدم غير مخول أو مراجع تابعة لمؤسسة أخرى | رفض الطلب دون كشف السياسة أو قبول تعديلها |
| A2 | قيمة أو مرجع غير صالح أو حقل مطلوب ناقص | تحديد موضع الخطأ وعدم اعتماد التغييرات حتى التصحيح |
| A3 | أهداف متناقضة أو طبقة واحدة مصنفة ثابتة وقابلة للتعديل في الطلب نفسه | عرض التعارض وعدم إسقاط أحد الشروط تلقائيًا |
| A4 | عملية إصلاح أو نوع تعديل خارج قدرات المحرك | توضيح عدم الدعم وعدم اعتماد الجزء غير المدعوم للتخطيط؛ لا يُحذف فحص مستقل من الكتالوج بسبب محدودية المحرك |
| A5 | تعذر التحقق من مرجع GitHub أو عضوية مؤثرة | طلب استكمال التحقق دون افتراض طرف أو عضوية أو قائمة استثناءات فارغة؛ يعاد التحقق من المدخلات المؤثرة عند UC07 |
| A6 | تغيرت النسخة المحفوظة أثناء التحرير | عرض التعارض وطلب مراجعة النسخة الأحدث؛ لا يضيع تعديل مسؤول آخر |
| A7 | تعذر حفظ النسخة أو سجل اعتمادها | لا يعرض نجاح الحفظ ولا يعتمد نسخة جديدة، وتبقى النسخة السابقة إن وجدت مرجعًا |
| A8 | إلغاء المستخدم قبل الحفظ | إنهاء محاولة التعديل دون اعتماد نسخة جديدة |

## قواعد التفسير والصلاحيات

- المسؤول يضبط السياسة والأهداف. المقيّم يختار نسخًا معتمدة عند تشغيل التقييم أو طلب الخطة؛ لا يمنحه ذلك صلاحية تعديلها. تفصل صلاحيات الاطلاع ضمن مصفوفة الصلاحيات القادمة.
- جميع الفحوص الـ24 ضمن نطاق تنفيذ المنصة المعتمد. اختيار فحوص لسياسة أو تشغيل معين يحدد نطاق ذلك التقييم، ولا يعني اكتمال تقييم الفحوص المستبعدة أو إسقاطها من نطاق المشروع.
- تعذر قراءة بيانات فحص مطلوب لا يؤدي إلى حذفه من السياسة أو احتسابه مستوفيًا. تعلن حدود الوصول في UC02، ويظهر أثرها عند تنفيذ UC05.
- حفظ سياسة أو أهداف جديدة لا يغير نتائج قديمة أو يغلق مخالفاتها، ولا يشغل تقييمًا أو خطة إصلاح تلقائيًا. تستخدم الطلبات اللاحقة نسخًا محددة، وتعالج المقارنة اختلاف المتطلبات صراحة.
- لا يعني قبول أهداف صحيحة إيجاد خطة لها. UC07 يتحقق من بيانات الحالة الفعلية ودعمها، ثم يبحث ضمن حدوده؛ وقد ينتهي دون خطة.
- هذا السيناريو يحفظ سياسة المؤسسة داخل المنصة؛ تطبيق تغيير إعدادات GitHub يظل يدويًا وفق النطاق المعتمد.
