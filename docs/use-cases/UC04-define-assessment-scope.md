# UC04 — تحديد نطاق التقييم

الحالة: تصميم مستهدف. التاريخ: 1 نوفمبر 2026.

| العنصر | الوصف |
|---|---|
| الهدف | حفظ نطاق قابل لإعادة الاستخدام يحدد ما سيُقيّم، والاتصال ونسخة السياسة اللذين سيُستخدمان |
| الطرف الرئيسي | المقيّم المخول داخل المؤسسة |
| المحفز | اختيار إنشاء نطاق تقييم أو تعديل نطاق محفوظ |
| المدخلات | المؤسسة، ومرجع الاتصال، ومعرفات المستودعات والفحوص المختارة، ونطاق كل فحص، ومرجع نسخة السياسة المعتمدة |
| الشروط السابقة | جلسة وعضوية وصلاحية إدارة نطاق التقييم؛ اتصال GitHub مُعدّ للمؤسسة ونسخة سياسة معتمدة يمكن للمقيّم استخدامها |
| النتيجة الناجحة | نطاق محفوظ بمرجع واضح يمكن اختياره لاحقًا عند طلب تقييم في UC05 |
| ضمان الفشل | لا يعتمد نطاقًا بمراجع غير مخولة أو مدخلات غير صالحة، ولا يغير تقييمًا سابقًا أو إعدادات GitHub |

## ما الذي يحتويه النطاق؟

| العنصر | المقصود |
|---|---|
| المؤسسة والاتصال | حدود البيانات المصرح بها ومصدر جمعها؛ لا يخلط النطاق اتصالات مؤسسات مختلفة |
| المستودعات | معرفات ثابتة لمستودعات مختارة من النطاق الذي يتيحه الاتصال |
| الفحوص | معرفات الفحوص المختارة من الكتالوج المعتمد، مع وجود قيمها المطلوبة في نسخة السياسة |
| نطاق الفحص | الفرع الافتراضي لفحوص الفروع في النطاق الأول، أو نطاق المستودع وما يتطلبه تعريف الفحص من مراجع إضافية |
| نسخة السياسة | المرجع المحدد الذي يوضح القيم والحدود والقوائم المعتمدة؛ لا يستبدل بأحدث نسخة بصمت |

مثال: تقييم المستودعين A وB باستخدام اتصال المؤسسة ونسخة السياسة P3، وتشغيل SC-01 وSC-02 وSC-03 وSC-10 على الفرع الافتراضي لكل مستودع. هذا مثال لمحطة التسليم الأولى؛ الفحوص الـ24 كلها ضمن نطاق تنفيذ المنصة المعتمد.

## المسار الأساسي

1. يختار المقيّم مؤسسته، ثم إنشاء نطاق أو فتح نطاق محفوظ. تتحقق المنصة من صلاحياته وانتماء النطاق والمراجع إلى المؤسسة.
2. تعرض المنصة الاتصال المُعدّ والمستودعات المصرح بها، وكتالوج الفحوص ونسخ السياسات المعتمدة المتاحة، مع وقت آخر تحقق من الاتصال وحدوده. يستخدم المسار ضوابط UC02 للوصول إلى قائمة المستودعات؛ لا يقبل اسم مستودع مدخلًا يدويًا بوصفه إثبات تفويض.
3. يختار المقيّم الاتصال ومستودعًا واحدًا على الأقل، والفحوص المطلوبة، ونسخة السياسة. يمكن إعادة استخدام نطاق محفوظ دون تغيير، أو تعديل اختياراته ضمن صلاحياته.
4. تحدد المنصة نطاق كل فحص وفق تعريفه. تستهدف فحوص الفروع الفرع الافتراضي في هذه النسخة من التصميم، وتظهر هذه الدلالة للمستخدم؛ لا تعني إضافة مستودع فحص جميع فروعه تلقائيًا.
5. تتحقق المنصة من اكتمال الاختيار وصحة المعرفات وانتماء المستودعات إلى النطاق المصرح به، ومن وجود القيم المطلوبة للفحوص في نسخة السياسة. توضح مشكلات الوصول المعروفة دون حذف فحص مختار أو تغييره إلى ناجح.
6. تعرض ملخصًا يشمل المستودعات، ونطاق الفحوص، والفحوص المختارة، ونسخة السياسة، وحدود الوصول المعروفة. يراجع المقيّم الملخص ويؤكد الحفظ أو يلغي التعديل.
7. تعيد المنصة التحقق من التفويض ومن عدم استبدال نسخة النطاق أثناء التحرير، ثم تحفظ المحتوى ومرجعه وسجل الإجراء بصورة متسقة. لا تستبدل تعديلات مستخدم آخر بصمت.
8. تعرض تأكيد الحفظ ومرجع النطاق. يستطيع المقيّم لاحقًا اختياره لتشغيل UC05؛ لا ينشئ الحفظ مهمة تقييم تلقائيًا.

## البدائل والاستثناءات

| الرمز | الحالة | السلوك المطلوب |
|---|---|---|
| A1 | صلاحية غير صالحة أو مراجع لمؤسسة أخرى | رفض الإجراء دون كشف بيانات النطاق أو المستودعات |
| A2 | اختيار فارغ أو معرف غير معروف أو قيم مطلوبة غير معرفة بالسياسة | توضيح موضع الخطأ وعدم اعتماد النطاق حتى تصحيحه؛ ضبط قيم السياسة من مسؤولها في UC03 |
| A3 | اتصال مفصول أو مستودع خارج نطاق الاتصال المصرح به | طلب اختيار اتصال أو مستودع صالح؛ لا يعتمد إدخالًا جديدًا لمجرد معرف المستودع |
| A4 | تعذر تحديث قائمة المستودعات أو إثبات الوصول إلى اختيار جديد | توضيح التعذر وعدم اعتماد الإضافة غير المتحقق من تفويضها؛ يبقى النطاق السابق محفوظًا إن وجد |
| A5 | نقص وصول معروف إلى بيانات فحص داخل مستودع مصرح به | إظهار القيد مع إبقاء الفحص المختار؛ تتحدد النتيجة الفعلية عند تنفيذ UC05، دون وعد بنجاح القراءة |
| A6 | لا يوجد فرع افتراضي حالي أو تعذر تحديده | توضيح الحالة وعدم افتراض اسم فرع. يعالج UC05 أثرها وفق متطلب الفحص وانطباقه وأدلته، دون الانتقال إلى فرع بديل صامتًا |
| A7 | تغير النطاق المحفوظ أثناء التحرير | طلب مراجعة النسخة الأحدث قبل الحفظ، دون الكتابة فوق تعديل آخر |
| A8 | فشل الحفظ أو إلغاء المستخدم | لا يعتمد نطاقًا جديدًا؛ يبقى المحتوى السابق إن وجد دون تغيير |

## قواعد الاستخدام مع UC05

- صلاحية النطاق المحفوظ لا تضمن استمرار الوصول إلى GitHub؛ تعاد مراجعة الوصول عند التنفيذ، ويمنع النطاق المحفوظ توسيع الوصول خارج ما يتيحه الاتصال حينها.
- يحفظ كل تقييم محتوى النطاق ونسخة السياسة اللذين بدأ بهما؛ تعديل النطاق لاحقًا لا يغير سؤال تقييم سابق أو أدلته.
- عند بدء التقييم، تثبت المراجع الفعلية للفروع المستهدفة وتظهر في النتائج. لا تخلط إعادة المحاولة نتائج فرعين إذا تغير الفرع الافتراضي؛ تغير النطاق يعلن عند المقارنة وإعادة التحقق.
- اختيار جزء من الفحوص يحدد تغطية ذلك التشغيل. لا يغير السياسة المعتمدة، ولا يعني أن الفحوص غير المختارة قد قُيّمت أو استُوفيت، ولا يسقطها من نطاق المشروع ذي الفحوص الـ24.
- حفظ النطاق لا يجمع الأدلة التفصيلية ولا يشغل محرك الإصلاح؛ تشغيل التقييم في UC05، وطلب خطة الإصلاح في UC07.
