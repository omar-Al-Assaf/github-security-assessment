# UC05 — تشغيل التقييم

الحالة: تصميم مستهدف. التاريخ: 1 نوفمبر 2026.

| العنصر | الوصف |
|---|---|
| الهدف | تقييم نطاق GitHub وفق نسخة محددة من سياسة المؤسسة، وحفظ النتائج وأدلتها وحدودها |
| الطرف الرئيسي | المقيّم أو مسؤول المؤسسة، وفق مسودة مصفوفة الصلاحيات |
| الطرف الخارجي | GitHub، عبر GitHub App المعتمدة |
| المحفز | اختيار المستخدم «تشغيل التقييم» |
| المدخلات | المؤسسة، والمستودعات والفحوص المختارة، ونطاق كل فحص، ونسخة السياسة، ومرجع الاتصال |
| الشروط السابقة | جلسة صالحة وعضوية وصلاحية تشغيل التقييم؛ نطاق محفوظ صالح تابع للمؤسسة واتصال مُعدّ له. جاهزية الاتصال الفعلية وقت التنفيذ تتحقق أثناء العمل |
| النتيجة الناجحة | تقييم محفوظ مع الأدلة والأحكام والمخالفات المثبتة، وحالة تشغيل كاملة أو جزئية معلنة |
| ضمان الفشل | لا يؤكد قبول مهمة لم تُحفظ؛ لا ينتج نجاحًا أمنيًا من بيانات ناقصة، ولا يستبدل التاريخ السابق |

## المسار الأساسي

1. يختار المقيّم مؤسسته ونطاقًا محفوظًا من UC04، ويراجع مستودعاته وفحوصه ونسخة السياسة المعتمدة، ثم يطلب التشغيل.
2. تتحقق المنصة من الجلسة وصلاحيات المستخدم وحدود المؤسسة وصحة النطاق والمدخلات.
3. تحفظ المنصة المهمة قبل تأكيد قبولها، وتثبت مراجع النطاق ونسخة السياسة والاتصال. تعرض مرجع المهمة وحالتها؛ يستمر العمل في الخلفية دون إبقاء طلب الويب مفتوحًا حتى النهاية.
4. يتحقق Worker من استمرار تفويض المهمة، بما فيه عضوية طالبها وصلاحية الإجراء والاتصال ونطاقه، ثم يبدأ محاولة تنفيذ ويسجل بدايتها وعدّادها بصورة دائمة قبل العمل. يظل نطاق القراءة محصورًا بمؤسسة المهمة وما يصرح به اتصالها.
5. يجمع بيانات GitHub المطلوبة، بما فيها الصفحات اللازمة، ويسجل المصدر ونافذة الجمع والأخطاء والحقول الناقصة.
6. يقيم الفحوص المختارة وفق نسخة السياسة المثبتة. يميز الانطباق والدعم والحكم الأمني عن حالة تشغيل المهمة؛ يوثق النتائج غير المحسومة وأسبابها.
7. يحفظ الأدلة والنتائج، وينشئ المخالفات المثبتة أو يربط ظهورها بسجلاتها الحالية وفق هوية المخالفة المعتمدة، دون تكرار المخرجات النهائية عند إعادة المحاولة.
8. يثبت اكتمال المهمة أو جزئيتها، ويتيح نتائجها وأدلتها وينشئ تنبيهًا داخل التطبيق للمستخدم المخول. تعثر التنبيه بعد إقرار النتيجة لا يعيد تنفيذ مهمة انتهت.

## المسارات البديلة والاستثنائية

| الرمز | الحالة | السلوك المطلوب |
|---|---|---|
| A1 | جلسة غير صالحة أو وصول غير مخول | يرفض الطلب دون تشغيل تقييم، ولا يكشف بيانات مؤسسة أخرى |
| A2 | مدخلات أو نطاق أو نسخة سياسة غير صالحة | يوضح سبب الرفض ويطلب تصحيح المدخلات؛ لا ينشئ تقييمًا صالحًا من نطاق غامض |
| A3 | تعذر حفظ المهمة قبل القبول | لا يعرض أن الطلب قُبل أو بدأ؛ يوضح تعذر تسجيله |
| A4 | فقد صلاحية GitHub أو غياب حقل أو صفحة | يوضح البيانات المتعذرة. نقص البيانات يجعل السؤال المتأثر غير محسوم؛ لا يثبت تعطيل ميزة أو غياب استثناء بمجرد غياب الحقل |
| A5 | فشل عابر أو انقطاع مؤقت أو حد طلبات | تعاد محاولة المهمة بعد تأخير مناسب، ضمن مهلة التنفيذ وبحد 3 محاولات إجمالًا. توجد حدود منفصلة لإعادة HTTP داخل المهلة؛ لا يصفر إعادة تشغيل Worker عداد المهمة |
| A6 | استنفاد المحاولات أو فشل دائم يمنع التنفيذ | تتوقف الإعادة الآلية وتسجل المهمة فاشلة مع السبب وتاريخ المحاولات. الفشل التشغيلي وحده لا يصبح مخالفة أمنية |
| A7 | بيانات كافية لبعض الفحوص فقط | تحفظ النتائج الممكنة، ومنها المخالفة المثبتة بدليل، وتعلن جزئية التشغيل. تظهر الأسئلة الأخرى غير محسومة مع أسبابها |
| A8 | فحص غير منطبق أو ميزة غير متاحة أو فحص غير مدعوم | يظهر التصنيف والسبب. عدم الانطباق بسبب مثبت لا يعد نجاحًا؛ إذا كانت السياسة تطلب ميزة ثبت تعطيلها، فذلك إخفاق للمتطلب |
| A9 | فشل التقييم الداخلي أو حفظ المخرجات | يسجل سبب المحاولة عند إمكان ذلك، ولا يثبت نجاح المهمة قبل حفظ مخرجاتها. يسترجع العمل المنقطع وفق حد المحاولات دون إقرار نتيجة نهائية مرتين؛ تعذر قاعدة البيانات يعالج عند استعادة الوصول |
| A10 | إلغاء أو فصل الاتصال أو فقد تفويض طالب المهمة قبل انتهائها | يوقف التنفيذ عند نقاط التحقق وقبل الإقرار النهائي، وتلغى المهمة غير النهائية مع حفظ ما جمع بوصفه غير مكتمل. طلب شبكة قائم قد يستمر إلى نهايته أو مهلته؛ لا يثبت الإلغاء زوال مخالفة ولا يستبدل نتيجة انتهت بالفعل. تغير الدور لا يلغي المهمة إذا بقي الإجراء مسموحًا |

## قواعد لا تتغير بين المسارات

- ثلاث محاولات تعني الأولى وإعادتين كحد أقصى، مع بقاء سجل المحاولات السابقة.
- الحكم الأمني: مستوفٍ، أو غير مستوفٍ بدليل، أو غير محسوم. حالات انتهاء التشغيل: مكتمل، أو جزئي، أو فاشل، أو ملغى. يحفظ الانطباق والدعم منفصلين.
- إعادة المحاولة تخص مهمة غير نهائية وخطأ عابر مع بقاء المحاولات والمهلة. لا يكفي وجود بيانات محاولة محفوظة لإعلان اكتمال تقييم؛ يلزم إقرار مخرجاته النهائية بصورة متسقة ودون تكرار.
- البيانات المجموعة ليست لقطة ذرية مضمونة؛ يحفظ زمن الجمع وحدود الاتساق. كل نتيجة مرتبطة بنسخة سياستها ودليلها.
- غياب مخالفة من جمع ناقص لا يغلق مخالفة سابقة، وتغيير السياسة لا يوصف وحده بأنه إصلاح للإعداد.
- الفحوص الـ24 معتمدة وتنفذ تدريجيًا؛ التنفيذ يخص الفحوص المختارة المدعومة، ويظهر غير المدعوم صراحة. الخطة الأمنية والاشتراك والصلاحيات تحدد توافر بعض البيانات.
- لا يولّد هذا السيناريو إصلاحًا تلقائيًا ولا يغير إعدادات GitHub. طلب الخطة UC07 وإعادة التحقق UC08 حالتان مستقلتان.
