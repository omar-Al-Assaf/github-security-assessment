# UC06 — متابعة معالجة المخالفات

الحالة: تصميم مستهدف. التاريخ: 1 نوفمبر 2026.

| العنصر | الوصف |
|---|---|
| الهدف | تنظيم العمل على مخالفة محفوظة بتحديد المسؤول وحالة المتابعة والتعليقات، مع الحفاظ على نتائج الفحص وأدلتها وتاريخها |
| الطرف الرئيسي | المقيّم أو مسؤول المؤسسة، وفق مصفوفة الصلاحيات المعتمدة |
| المحفز | فتح مخالفة واختيار تحديث متابعتها |
| المدخلات | مرجع المخالفة ونسختها الحالية، والتحديث المطلوب للمسؤول أو الحالة أو التعليق، وسبب الإغلاق الإداري عند اختياره |
| الشروط السابقة | جلسة وعضوية وصلاحية متابعة صالحة؛ مخالفة مسجلة ضمن المؤسسة ومرتبطة بنتيجة ودليل محفوظين |
| النتيجة الناجحة | تحديث محفوظ للمتابعة مع تسجيل الفاعل والوقت والتغيير، دون استبدال النتيجة الأمنية السابقة |
| ضمان الفشل | لا يحدث تعديل عابر للمؤسسات، ولا يعلن نجاح تحديث لم يُحفظ، ولا يعد الإغلاق اليدوي دليلًا على زوال المخالفة |

## الفرق بين المتابعة والنتيجة الأمنية

| ما يستطيع المستخدم تحديثه هنا | ما يحتاج تقييمًا وأدلة |
|---|---|
| المسؤول عن المعالجة، وحالة المتابعة والتعليق | هل ما زال المتطلب غير مستوفٍ، أم أثبت تقييم جديد زوال المخالفة؟ |
| تسجيل أن المعالجة أُنجزت وبانتظار التحقق | التحقق من إعدادات GitHub الجديدة في UC08 |
| إغلاق إداري مع سبب صريح | إثبات الإصلاح بالنسبة للمتطلب والنطاق نفسيهما |

في هذا التصميم يمكن تسجيل المتابعة باعتبارها مفتوحة، أو قيد المعالجة، أو بانتظار التحقق، أو مغلقة إداريًا. هذه أوصاف للعمل الإداري؛ لا تمنح المستخدم خيار تعديل حكم الفحص إلى «مستوفٍ» أو «زالت بالتحقق». تعرض الحالة الإدارية وأحدث نتيجة تحقق ووقتها بصورة مميزة.

## المسار الأساسي

1. يختار المقيّم مؤسسته ثم مخالفة محفوظة. تتحقق المنصة من صلاحية الاطلاع والمتابعة وانتماء المخالفة إلى المؤسسة.
2. تعرض المنصة السؤال والمتطلب والنطاق والنتيجة ودليلها، وأحدث تحقق متاح، والمسؤول وحالة المتابعة والتاريخ. لا تكفي عبارة الحالة وحدها لفهم الوضع الأمني.
3. يختار المقيّم تعديل أحد حقول المتابعة: إسناد المعالجة إلى عضو فعال في المؤسسة، أو تحديث الحالة، أو إضافة تعليق. الإسناد لا يغير دور العضو أو يمنحه صلاحيات إضافية.
4. إذا اختار الإغلاق الإداري، يقدم سببًا ويظهر له أن هذا الإجراء لا يثبت الإصلاح. وإذا أعلن انتهاء المعالجة، يستطيع اختيار «بانتظار التحقق»؛ يظل قوله وصفًا للعمل الذي أجراه حتى تنفيذ UC08.
5. تتحقق المنصة من صلاحية الإجراء والقيم والمراجع، ومن عضوية المسؤول المختار، ووجود سبب الإغلاق عند لزومه. لا تسمح بتعديل نتيجة الفحص أو دليلها من هذا الطلب.
6. تعيد المنصة التحقق من التفويض ومن النسخة الحالية للمخالفة قبل الحفظ. إذا حدث تحديث مؤثر منذ فتحها، تطلب مراجعة الوضع الجديد بدل الكتابة فوقه بصمت.
7. تحفظ حقول المتابعة وسجل التغيير والفاعل والوقت بصورة متسقة، مع إبقاء التعليقات والتاريخ السابق. لا تنشئ مخالفة جديدة لمجرد إسنادها أو تغيير حالتها.
8. تعرض تأكيد الحفظ والمتابعة المحدثة بجانب أحدث حكم أمني ومرجعه. يتاح طلب إعادة التحقق عبر UC08 للمخول بذلك، كإجراء مستقل.

## البدائل والاستثناءات

| الرمز | الحالة | السلوك المطلوب |
|---|---|---|
| A1 | مستخدم غير مخول أو مخالفة تخص مؤسسة أخرى | رفض الطلب دون كشف بيانات المخالفة أو تعديلها |
| A2 | مسؤول معين خارج المؤسسة أو عضويته غير فعالة | رفض الإسناد وطلب اختيار عضو صالح؛ لا تنشأ عضوية جديدة تلقائيًا |
| A3 | قيمة حالة غير صالحة أو سبب إغلاق مفقود | تحديد الخطأ وعدم اعتماد التحديث حتى التصحيح |
| A4 | محاولة تغيير الحكم أو الدليل ضمن طلب المتابعة | رفض الحقول غير المسموحة؛ تحديث الحكم يتبع التقييم والتحقق |
| A5 | تعارض مع تحديث أحدث، بما فيه تحقق اكتمل أثناء التحرير | عرض الوضع الحالي وطلب مراجعته قبل التحديث؛ لا تضيع نتيجة التحقق أو متابعة مستخدم آخر |
| A6 | فشل حفظ التحديث أو سجل التغيير | لا يعرض نجاح التحديث، وتبقى آخر حالة محفوظة مرجعًا |
| A7 | إلغاء المستخدم قبل الحفظ | تبقى المخالفة ومتابعتها دون تعديل |

## العلاقة بإعادة التحقق والتاريخ

- نشأة المخالفة وربط ظهورها المتكرر بنتائج الفحص يتبعان UC05 وهوية المخالفة المعتمدة؛ هذه الحالة تدير متابعتها، ولا تكرر سجلها.
- تسجيل «بانتظار التحقق» لا يشغل مهمة تلقائيًا. يتطلب بدء UC08 طلبًا مستقلًا محفوظًا من مستخدم مخول.
- إذا أثبت تقييم لاحق وجود مخالفة مغلقة إداريًا، يعاد فتحها وفق UC08 مع حفظ سبب الإغلاق السابق والظهور الجديد. أما تعذر القراءة أو فشل المهمة فلا يثبت عودتها أو زوالها.
- تغيير المسؤول أو الحالة أو تعليق لا يغير أدلة التقييم القديم. كذلك فتح المتابعة يدويًا لا يثبت وحده أن المخالفة عادت بعد تحقق سابق من زوالها.
- هذه الحالة لا تنفذ تعديلًا على GitHub. يطبق المسؤول المعالجة خارجيًا، ثم تتحقق المنصة من الوضع الجديد وفق النطاق المدعوم.
