# UC08 — إعادة التحقق بعد المعالجة

الحالة: تصميم مستهدف. التاريخ: 1 نوفمبر 2026.

| العنصر | الوصف |
|---|---|
| الهدف | الحصول على تقييم جديد ومقارنته بالمرجع السابق، لتحديد هل زالت المخالفة ضمن نطاق التحقق |
| الطرف الرئيسي | المقيّم أو مسؤول المؤسسة، وفق مسودة مصفوفة الصلاحيات |
| المحفز | اختيار «إعادة التحقق» من مخالفة أو تقييم سابق، بعد معالجة يدوية أو للتحقق من الوضع الحالي |
| الطرف الخارجي | GitHub، عبر الاتصال المصرح به |
| المدخلات | مرجع التقييم والمخالفة إن وجدت، والنطاق والفحوص المستهدفة، ونسخة السياسة، ومرجع خطة الإصلاح وأهدافها عند ارتباط الطلب بها |
| الشروط السابقة | جلسة وعضوية وصلاحية تشغيل التقييم، ومرجع محفوظ تابع للمؤسسة. قول المستخدم إنه عالج المخالفة لا يثبت زوالها |
| المخرج | تقييم جديد بأدلته، ومقارنة مفسرة، وتحديث موثق للمخالفات التي أمكن التحقق منها |
| ضمان الفشل | يحتفظ بالتقييم والأدلة السابقة، ولا يغلق مخالفة بسبب نقص البيانات أو فشل التشغيل أو اختلاف السؤال |

## المسار الأساسي

1. يختار المقيّم مخالفة أو تقييمًا سابقًا ويطلب إعادة التحقق من النطاق المستهدف.
2. تتحقق المنصة من صلاحياته وملكية المراجع وحدود المؤسسة وصحة النطاق.
3. تسجل مهمة تقييم جديدة مرتبطة بالمرجع السابق والمخالفات والخطة عند وجودها. تثبت نسخ السياسة والأهداف والنطاق؛ تستخدم المتطلبات السابقة افتراضيًا للمقارنة، وتوثق اختيار سياسة مختلفة صراحة.
4. تنفذ دورة [UC05](UC05-run-assessment.md) لجمع بيانات جديدة وتقييمها وحفظ الأدلة والنتائج. تطبق حدود المحاولات على مهمة التقييم نفسها؛ لا تنشأ دورة إعادة أخرى فوقها تضاعف العدد.
5. تقارن المنصة النتائج للسؤال والنطاق والمتطلبات المتكافئة. تميز تغير الإعدادات عن تغير المتطلبات أو النطاق أو دلالة المقيّم. تعرض نافذة الجمع وأساس كل حكم وحدوده.
6. لكل مخالفة مستهدفة، إذا أثبتت البيانات الكافية زوالها بالنسبة للمتطلب نفسه، يعد قرار تسجيل زوالها بالتقييم الجديد. إذا بقيت مثبتة، تبقى مفتوحة أو يعاد فتحها مع ربط ظهور التقييم نفسه؛ لا يكرر UC08 ظهورًا سبق أن سجله UC05 للتقييم والمخالفة نفسيهما. تعذر الحسم لا ينتج قرار إغلاق، وتوثق المحاولة غير المحسومة.
7. إذا ارتبط الطلب بخطة إصلاح، يعاد حساب أهداف السماح والمنع على القواعد والعضويات الجديدة داخل النموذج المدعوم. يعرض أثر التعديل على الأهداف مع حدود التحقق؛ لا يعاد استخدام مصفوفة الخطة القديمة كدليل جديد.
8. تحفظ المقارنة والتحديثات الناشئة عنها وتاريخ المخالفات وروابط الأدلة بصورة متسقة، ثم يعرض للمقيّم ما تحقق وما بقي أو تعذر التحقق منه. لا يؤكد زوال مخالفة قبل حفظ القرار، ولا تستبدل النتائج السابقة بالأحدث.

## البدائل والاستثناءات

| الحالة | السلوك المطلوب |
|---|---|
| طلب غير مخول أو مرجع لمؤسسة أخرى | يرفض دون كشف البيانات أو تشغيل مهمة |
| تعذر حفظ المهمة الجديدة | لا يؤكد قبول الطلب، ولا يعيد تسمية المهمة القديمة باعتبارها تقييمًا جديدًا |
| تعذر حفظ المقارنة أو تحديثات التحقق | لا يؤكد قرارًا جديدًا بزوال المخالفة. تبقى أدلة التقييم المحفوظة والظهور المثبت الذي سجله UC05، ولا تكرر معالجته عند استرجاع المقارنة |
| إلغاء مهمة التقييم أو فصل الاتصال | تتبع حالة الإلغاء في UC05؛ لا ينتج الإلغاء قرارًا بزوال المخالفة |
| فشل GitHub أو انقطاع Worker أو تعثر الحفظ | تتبع ضوابط UC05: 3 محاولات إجمالًا بحد أقصى وضمن المهلة، مع عداد دائم ومخرجات نهائية غير مكررة. فشل التشغيل لا يغلق مخالفة |
| بيانات ناقصة لسؤال مستهدف | يسجل عدم الحسم والسبب وتبقى الحالة السابقة؛ لا يصبح غياب البيانات نجاحًا أو دليلًا على زوال المشكلة |
| نتيجة جزئية | يقيم كل سؤال ومخالفة على حدة؛ نجاح التحقق من أحدها لا يغلق البقية، ونقص بيانات فحص آخر لا يبطل دليلًا كافيًا للسؤال الذي تحقق |
| تغير السياسة أو النطاق أو دلالة السؤال | يوثق الفرق؛ لا يعد اختلاف النتيجة وحده إصلاحًا. إزالة المتطلب أو سحب المستودع من النطاق تحتاج سببًا مستقلًا عن «زالت بالتحقق» |
| اختفاء عنصر من النتائج | لا يكفي وحده للإغلاق. قد يثبت زوال مخالفة العنصر بعد جرد مكتمل للبيانات اللازمة، مثل إزالة استثناء غير معتمد؛ تعذر الوصول إليه لا يثبت إزالته |
| قيد مؤثر غير مدعوم أو عضويات ناقصة عند تحقق خطة | تبقى نتيجة الهدف غير محسومة أو غير مدعومة. لا تدعي المنصة أن الخطة حققت جميع الأهداف |
| أغلق المستخدم المخالفة إداريًا ثم أثبت التقييم وجودها | يضاف الظهور الجديد ويعاد فتحها؛ يحفظ سبب الإغلاق السابق دون تحويله إلى دليل تقني |

## حدود الاستنتاج

- «زالت بالتقييم» حكم بالنسبة للسؤال والدليل والزمن والنموذج المدعوم، وليس ضمانًا دائمًا لأمان المستودع.
- إعادة قراءة الإعدادات أو إعادة حساب النموذج ليست اختبارًا حيًا لتنفيذ push أو merge؛ يجب بيان أساس النتيجة. الاختبارات السلوكية الحية لها مختبر مصرح به مستقل.
- لكل طلب إعادة تحقق تقييم جديد وتاريخ مستقل، مع استمرار هوية المخالفة وفق تعريفها المعتمد. لا يمحى سجل المحاولات السابقة.
- نجاح تشغيل المهمة لا يساوي استيفاء الضابط، وفشل المهمة لا يثبت مخالفة أمنية بذاته.
